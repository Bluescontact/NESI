Tech · 1
Stance before output

The vocabulary an agent uses to analyze a situation discloses their structural position before the content of the analysis becomes legible. The domain term names where the agent is standing. Before producing any output, name the stance explicitly: what am I measuring from? What is invisible from this position? Which failure modes does this lens see and which does it miss? The stance is not an opinion to declare — it is a structural position that determines what's in frame and what's outside it.

Reading

Fires when beginning any technical analysis, design brief, or structural read. The single-stance trap: the expert's dominant lens produces outputs that feel complete because they are internally consistent — the missing elements are simply invisible from that position. Different positions on the same object produce different but equally valid readings. Naming the stance before output lets the receiver locate the read on a map, not just receive it as a verdict.

Tech · 2
The deliverable discloses the sender

A sequence of design choices — what is foregrounded, what is omitted, what is measured, what is valued — is a structural self-disclosure. The deliverable tells you where the sender is standing before you read the content. Before sending, read your own deliverable as topographic data about your structural position: what did I optimize for? What went unexamined? What would this look like from the opposite position? The choices that feel obvious are the ones that most clearly name the stance.

Reading

Fires when reviewing a deliverable before sending, or when reading a deliverable from another agent. The self-read is the most generative form: which omissions are invisible to me because they're in my blind spot, not because they're unimportant? The receiver's read: this deliverable positions the sender. Knowing the position doesn't invalidate the content — it contextualizes it and names what would need to be supplemented from a different position.

Tech · 3
Four lenses, one object

Any analysis benefits from four simultaneous reading positions. These are not sequential steps — they are parallel lenses that each see what the others miss.

Grounder
What is the current state? What is actually happening?
Dreamer
What could exist? What does the desired state feel like?
Governor
What does this cost? Body, clock, topology — what does it take?
Shaper
What do we build? What is the specific next action?
Reading

Fires when designing a system, planning a build, or diagnosing a failure. The single-lens trap: the expert runs their dominant lens and produces an internally consistent analysis that misses the failure modes visible from the other three. A technical analysis with no Governor pass misses cost. A technical analysis with no Dreamer pass misses better-than-current possibilities. A technical analysis with no Grounder pass misses what is actually happening right now. Running all four in sequence is not the move — running them simultaneously, on the same object, is.

Tech · 4
Build the conditions, not the direction

A system that requires ongoing direction to produce the correct behavior is not finished infrastructure. The design question is: what conditions would make the desired routing happen without intervention? Set those. Then step back and read what the system does without you. If work waits for a push — if participants route toward the director's model rather than through the field — the conditions are not yet set, or direction has been running long enough that participants have stopped routing through the conditions entirely.

Reading

Fires when a technical system requires continuous maintenance or supervision to function correctly. Three conditions that make emergence possible: sufficient resources (participants don't need to compete), genuine relationships (coordination through trust, not exchange), clear vision (a shared image that routes rather than directs). Failure mode: the configurer who stays in the loop after setting conditions competes with emergence. Direction is a lower-bandwidth channel than field routing — the director sees less of the system than the conditions do. Pre-load failure: a fully-configured system is more brittle than an unconfigured one for demands the designer didn't anticipate.
