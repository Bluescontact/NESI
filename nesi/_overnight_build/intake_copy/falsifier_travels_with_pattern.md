# The Falsifier Travels With the Pattern

*Provenance: Same-quartet / tensegrity reconciliation, 2026-07-18 · slug: falsifier-travels-with-pattern · instantiated in tools/recognition/falsifier_gate.py 2026-07-19 (built before canon named it) · PROMOTED 2026-07-24*
*Library: EXTENDS · dissolution_encoded_at_origin.md — that pattern encodes an exit condition into a relationship at adoption; this one encodes the artifact's own preserved objections as inseparable identity. Delta: relational telos vs. provenance-placement of counter-material.*

---

## The mechanism

A pattern's against-side — the preserved objections raised against it and the condition under which it would be shown false — must ride welded to the artifact when it crosses into canon. It may not be archived to a separate cautions file, a footnote, or a downstream review doc. The disproof-condition is part of the pattern's identity, captured at the moment the pattern is named, not appended after it has already been trusted.

Two moves make it: **mark-time capture** (the falsifier is written when the pattern is authored, in the same act, so the pattern never exists in a state where its own disproof is not yet attached) and the **archive-off prohibition** (the counter-material cannot later be relocated away from the artifact to tidy it — relocation is a structural edit to the pattern, not housekeeping). A pattern that transmits with its objections stripped is a different, weaker object wearing the same name.

The distinction it draws is against provenance-laundering: canon that carries only the confident face of a pattern, with the cautions filed elsewhere, reads as more settled than it is. Welding the against-side on keeps the reader's trust calibrated to what the pattern actually earned.

---

## Failure modes

**Costume without machinery (the load-bearing against-case, preserved per the pattern's own rule).** As stated, this pattern has *capture* and *transport* but no *compiler* — it does not specify how a raised objection becomes a firable condition — and no *discharge* — it does not say what happens when the falsifier fires (does the pattern fall, get amended, get re-marked?). Without those, "the falsifier travels with the pattern" is an inseparability rule about where counter-material is *filed*, not a falsification *mechanism*. And the library already practices exactly that filing discipline as house style. This is the real COMPOST case, and it is welded here rather than archived off, because archiving it off is the precise move the pattern forbids.

**Decorative travel.** The against-side rides along but is never read, never compiled, never fires — present as ornament. Travel that changes nothing about how the pattern is used is indistinguishable from house style.

---

## Edges

Whether this is a standalone pattern or a naming of existing house style turns entirely on the compiler/discharge gap above. If a later build gives it a compiler (objection → firable predicate) and a discharge (fired → amend/fall/re-mark), it becomes a mechanism and the distinction from house style is earned. Until then it stands as an inseparability rule whose whole weight is the archive-off prohibition — which is real, but thin.

Its own instance is the strongest evidence for it: `falsifier_gate.py` welded the falsifier fields into the gate before this pattern was canonized — the machine ran the discipline before canon had language for it. Whether that instance generalizes or is the only place it has teeth is the open question.

---

## Falsifier

If a pattern can cross into canon with its disproof-condition stripped to a separate file and lose nothing — if archiving-off the against-side changes nothing about how the pattern is read, trusted, or used — then "travels-with" is decorative, and this is house style, not a pattern. The test is direct: take a canon pattern, move its objections to a cautions file, hand both to a fresh reader, and see whether their calibration shifts. If it does not, this pattern is false.
