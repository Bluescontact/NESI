## Statement

When the body that finds a failure, the authority that marks it, and the hand that fixes it are one body on a live surface, detection and ratification collapse into a single event — no ticket, no triage, no translation loss. In this regime a found bug is a successful measurement, and the spec is not violated by friction but written by it. The pattern exists only under three hinges — one sovereign user, same-day fix capacity, a surface cheap enough to go live unratified — and removing any one does not weaken it; it makes it undefined.

## Mechanism

**Role collapse.** Build candidate → use live → the body finds the failures → fix → promote. Finder, ratifier, and fixer are the same body, so no reporting layer dissipates the somatic signal. This separates the pattern from generic dogfooding, whose loop passes through tickets, repro steps, and prioritization.

**Sign inversion.** A live-found failure is evidence the instrument is reading. A week with zero found failures means the sensor is dead, not that the design is right. Found-failure rate is a liveness metric, not a defect count.

**Register inversion — the bug authors the spec.** A bug here is not a deviation from a spec; it is the body's articulation of a spec that never existed. The verified kernel: chassis v2→v3 in one day (2026-07-02) — two bugs found by live hands (undebounced ▶ fired 4×; armed edge could not release), both fixed before promotion, and the click-economy spec ("n marks = n+1 clicks") stated from felt use, not design review.

## What use cannot ratify — the boundary set (the pattern's honest content)

1. **The untouchable.** Off-screen state, data loss, security produce no felt friction — silently under-ratified. Scope is limited to interaction surfaces until a second, non-somatic channel exists.
2. **Habituation masquerading as coherence.** A surface used daily grows grooves; friction vanishes because the hand adapted. Every bug found by use has a shadow — the bug use learned to avoid. Without a de-habituation move (fresh hands, cold start, deliberate misuse — none yet instantiated), the ratification event is unfalsifiable.
3. **Cadence selects fast failures.** Same-day promotion sees only failures that announce within one sitting; drift and fatigue-under-repetition are invisible. The source week shows its own shadow: v2 was ratified and superseded the same day — "ratified" here means "ratified-today," provisional in a way the word conceals.
4. **Counterfeit ratification.** With no primary event on record, "my body found it" is indistinguishable from design reasoning wearing a somatic story. The mechanism whose point is that a felt-read cannot be faked becomes, once named, a phrase fluency can produce. Closer: one recorded instance (bug · felt-read · fix · promotion · timestamp).

## Jurisdiction

Inside-membrane law: governs what the maker's own body keeps touching. `inhabitable_without_author` governs what crosses to other bodies — inner and outer halves of one gate, split at the crossing point. If the chassis ever ships (OSG tools, the kit), the switch between regimes must be named at the crossing; nothing in canon currently names it. At N≥2 users the pattern is undefined (no aggregation rule for whose felt-read ratifies) — what replaces it in multi-node work is open.

## Falsifier

A spec written from live-found failure that proves wrong on second contact (the fix re-tested against a memory of a read, not a read); or a de-habituation pass that surfaces a routed-around bug the live hands ratified over — either event bounds the pattern tighter than stated.
