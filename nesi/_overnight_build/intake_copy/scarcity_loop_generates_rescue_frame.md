# Scarcity Loop Generates Rescue Frame

---

## The mechanism

The mechanism is frame capture, not information failure. The actor typically has access to the replacement cost — they can look it up. What scarcity changes is the evaluative axis: the question shifts from "what does a working system cost" to "what does saving this system cost next." These produce structurally different action sets. The first opens a comparison class. The second forecloses it — not by hiding information but because the frame doesn't generate the query.

Every action taken from inside the loop reinforces the rescue frame while consuming resources that could have funded exit. The loop is self-sealing: each rescue attempt is evidence the frame is working, never evidence the frame is wrong.

---

## The self-reinforcing structure

Each rescue attempt produces two outputs: a result (partial fix, stabilization, delay) and a commitment (time, money, social capital deployed). The commitment deepens sunk cost. The result, even if modest, validates the rescue frame as operative. Failure of a rescue attempt rarely breaks the frame — it generates the next rescue attempt, often escalating: more expert input, more hours on settings, more sophisticated interventions.

The loop terminates on depletion, not on decision. The rescue frame rarely breaks by rational comparison; it breaks when resources run out and rescue becomes physically impossible. At that point replacement happens under maximally bad conditions — minimum capital, minimum time, maximum pressure.

---

## Expertise conscription as the fuel mechanism

When the rescue frame is active, proximate expertise gets pulled into the loop not as a diagnostic agent but as rescue fuel. The expert's job, inside the frame, is to find the fix, not to evaluate the frame. The expert's comparative knowledge — replacement cost, system life expectancy, failure probability — is suppressed by the frame even when the expert holds it. This is not dishonesty; it is frame capture. The structural tell is directionality: in a decision-open frame, expert input can produce a stop; in a rescue frame, expert input can only produce a next attempt.

See [[expertise_conscripted_as_mirror]] for the mechanism on the expert's side; [[expertise_conscripted_as_rescue_fuel]] for the stop-signal that breaks the fuel loop.

---

## Secondary failure mode

The loop is mistaken for diligence from outside. Sustained rescue effort looks like responsible stewardship, exhausting options before committing to cost. This social reading reinforces the loop — it is legible as virtue rather than frame capture.

---

## Relationship to Rescue Frame Occlusion

[[rescue_frame_occlusion]] names the cognitive architecture: the pre-deliberative substitution that forecloses the comparison before deliberation can begin. This pattern names the temporal dynamics: how the loop runs, what fuels it, and why it terminates on depletion rather than decision. They are distinct:

- Scarcity Loop is the mechanism that keeps the loop running — why rescue attempts generate their own continuation.
- Rescue Frame Occlusion is the epistemic architecture — why the comparison isn't available in the first place.

---

## Edges

The pattern assumes the replacement path is genuinely available — but sometimes it isn't, and the rescue frame is the only viable frame (no capital, no credit, no time window). How do you distinguish a scarcity loop from a legitimately constrained actor doing real triage? The structural test: whether the replacement query is ever generated and rejected, versus never generated at all. The distinction is hard to observe from inside.

The loop's relationship to hope is unresolved. Rescue framing may be doing psychological work that replacement framing destroys — sustaining agency when the real cost of seeing the replace path clearly is intolerable.
