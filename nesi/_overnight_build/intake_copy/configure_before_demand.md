# Configure Before Demand

## Transferable Form

Demand-response quality is a function of pre-demand configuration, not real-time routing capacity. Configuration determines what paths exist when demand fires; routing selects among available paths. Without configuration, every demand is a novel event requiring path-creation under load. The work that looks like response is mostly the work of configuration — which happened earlier, and is invisible at the moment of success.

---

## Development

The mechanism appears across four independent domains, each naming a different surface of the same structure:

**Material (prestress / tensegrity):** a structure under load holds because tension was pre-loaded before the load arrived. The rigid members do not touch; the tension network distributes the force. When the load comes, there is no routing problem — the paths are already present. A structure without prestress receives the same load as a point event requiring real-time support.

**Conversational (questions as structural events):** a question reorganizes the room before any response. Participants are already positioned by the question's frame when they begin to answer. The most powerful version is the question asked before the meeting — the unnamed question that configures what is thinkable before anyone arrives. The response looks like it comes from the participant; it comes from the configuration.

**Attractor (future-image as pull):** a felt image of a desired future configures the system's direction before any specific choice is made. Deliberate navigation aims at a goal. Attractor-based navigation moves toward an image without being pushed — obstacles are routed around because the field reorganizes, not because the navigator recalculates. The image does the work that conscious deliberation would otherwise require.

**Relational (conditions over direction):** when a convener sets conditions — adequate resources, genuine relationships, visible adjacency — collaborative work emerges without direction. The configuration precedes the demand; participants route through it without being pushed. The convener who continues to direct after setting conditions disrupts the routing because direction competes with the field.

The structural invariant across all four: **the pre-load is the primary variable.** Real-time routing selects among available paths. Configuration creates the paths. These are not interchangeable — routing capacity does not substitute for absent configuration. The system scrambles when configuration is absent because it must create paths and route simultaneously under load.

---

## Falsifier

Present the same demand to a pre-configured and an unconfigured system under equivalent pressure. If outputs are indistinguishable, configuration is not the variable — real-time routing capacity is sufficient, and this pattern adds nothing.

The evidence across domains: outputs are not indistinguishable. Tensegrity structures hold loads that unbraced structures cannot. Appreciative Inquiry's simultaneity principle — the inquiry is the intervention, not the response — names the mechanism by which conversational pre-load exceeds what responsive facilitation can produce. Attractor-based navigation routes around obstacles that goal-based deliberation stalls on. Conditions-based emergence produces coordination that directed management cannot replicate at scale.

If you find a domain where unconfigured real-time routing matches configured pre-load performance, that is a falsifying instance.

## Edges

**The invisibility edge:** configuration work does not look like work at the moment of demand. The demand fires; the routing happens; the result appears. The configuration is not visible in the success case — it has been absorbed into the structure. This makes configuration systematically under-credited. The person who asked the right question the day before the meeting, the convener who set conditions before the collaboration, the builder who loaded the structure before the load arrived — their work is the success, and it is absent from the success story. Cross-reference: [[catalysis_without_claim]].

**The wrong-demand edge:** configuration precedes demand and cannot be updated in real time. A system configured for chronic threat routes gift as danger, rest as vigilance failure, abundance as a trap. The routing is confident and fast — the configuration is load-bearing — but the demand the configuration is optimized for is not the demand arriving. The correctly configured system and the incorrectly configured system are indistinguishable at the moment of demand; the difference only appears in the output. Cross-reference: [[translated_origin_failure_mode]] (directional variant: chronic-threat prestress as translation vector).

**The stale-configuration edge:** a configuration set for conditions that have since changed continues to route for the old conditions. The attractor field persists after the conditions that generated it have changed; the structure is pre-loaded for a world that is no longer present. Unlike the wrong-demand edge (where the configuration was never appropriate), the stale edge involves a configuration that was once correct and has not been updated. Cross-reference: [[future_image_as_pull]] (default-future-trap: image that cannot be updated becomes a trap).

**The configure-for-whom edge:** in delegation, the holder configures the discharge condition (gate_as_f4); in relational fields, the convener configures the conditions. Configuration is not self-distributing — someone does it, and the question of who is the configurator is structurally consequential. When the configurator's frame is the only frame available, the configuration is a single point of load. Cross-reference: [[gate_as_f4]] (holder's definitional obligation = configure-before-demand at delegation layer), [[witness_as_origin]] (second origin as configurator of an independent frame).
