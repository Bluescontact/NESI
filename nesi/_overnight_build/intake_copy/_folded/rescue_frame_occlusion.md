# Rescue Frame Occlusion

---

## The mechanism

When a system enters a scarcity loop, the operative question shifts — not by deliberation but by frame substitution that occurs before deliberation begins. "What does a working system cost?" is replaced by "how do I save this one?" These are not two answers to the same question. They are two frames that produce incompatible action sets.

The substitution is not experienced as substitution. It feels like focus, like responsibility, like doing what must be done. A person operating with full intelligence, full information, and full intention inside the rescue frame will not generate the replacement comparison — not because they are incapable, but because the frame does not request it. The viable path exists in the territory. It does not exist inside the frame.

The occlusion is architecturally produced.

---

## Structure

Two questions occupy the same slot in the decision architecture. Only one is active at a time. Scarcity installs rescue. Rescue is sticky because each incremental investment re-triggers loss-aversion: now there is more sunk cost, so replacement costs "more" relative to the rescue frame's accounting. The loop is self-reinforcing not because the actor is irrational but because the frame forecloses the comparison that would reveal the loop.

The threshold at which rescue cost exceeds replacement cost exists. It is not marked. It is crossed in the dark.

---

## Four failure modes

**Partial rescue victories:** the system is saved at a cost that exceeds replacement cost — but the comparison was never made, so the overpayment is invisible. The frame registers the save as success.

**Sequential rescue:** each rescue creates conditions for the next rescue. The loop continues until the system fails catastrophically or external constraint forces frame change.

**Frame confusion under advice:** an advisor who names the replacement path is heard as not understanding the situation. From inside rescue, replacement advice sounds naive — it ignores all the work already done. The advisor's accurate read is processed as evidence they lack context, not as evidence the frame is wrong.

**Threshold invisibility:** there is a point at which rescue cost exceeds replacement cost. That threshold is not marked. The actor crosses it without knowing.

## What breaks it

The frame does not break from inside by deliberation — the deliberation cannot be generated from inside the frame. Frame change occurs through:

- Resource exhaustion (catastrophic termination, worst conditions)
- External constraint that forces the comparison (a third party who holds the replacement cost prominently enough that the frame cannot absorb it)
- Pre-loop installation of a comparison trigger (a cutoff set before the frame installs — see [[consented_ledger]]'s cutoff doctrine: the cutoff is a pre-loop instrument, not an in-loop one)

The reliable intervention window is pre-loop, before the frame installs. Every in-loop instrument can be operationally captured.

---

## Edges

Whether the pattern is recoverable from inside — whether there is a trigger that reinstalls the replace frame without external intervention — is untested. The pattern implies it is not self-correcting.

The relationship between scarcity and frame installation: scarcity appears to be the trigger, but the prior condition may be attachment to the existing system (identity, investment, familiarity). If attachment is the real driver, scarcity only accelerates an occlusion already forming — which changes what intervention is possible.

Whether rescue frame occlusion is distinguishable from rational incremental repair when replacement is genuinely unavailable: the structural test is whether the replacement query is ever generated and rejected versus never generated at all. In genuine resource constraint, rescue may be the only available frame because replacement is not a real option. The pattern holds only when replacement is in-territory but out-of-frame.
