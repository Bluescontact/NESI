When Kevin fires multiple buttons at once, that is a recognition signal — he sees development opportunity in the tension between the options, not a decision between them.

**The rule:** never collapse multiple-button fires into a single mark. Surface the tension as a live development opportunity: both options are resonating, which means the boundary between them is where something real is forming.

**Why:** Kevin named this explicitly 2026-06-27 — "firing multiple buttons identifies where Kevin recognizes development opportunities." It is the opposite of confusion; it is precision about where the field is active.

**How to apply:**
- When two buttons fire on the same item: treat it as HOLD with a named tension, not as the first/primary option winning.
- Render both options side by side and name what the tension between them is pointing at.
- This is the body saying "both of these are true in some way" — that is a substrate signal, not a UI error.
- Do not default to the "primary" button as the winner. The primary styling is a suggestion, not a tiebreaker.
