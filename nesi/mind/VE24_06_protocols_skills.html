Group B

The pre-flight manifest mechanism, as PROTOCOLS.md states it.

PROTOCOLS.md's "Pre-flight Protocol" section (lines 445–503) sets the boot-path rule that any operation with real consequence — a write, a send, anything not trivially undoable — stops for a six-field manifest and Kevin's explicit go-ahead before executing. The skill-declared-manifest clause is the last paragraph of that section:

"Skill-declared manifests: when a skill file carries a `manifest: {do, touches, size}` block in its frontmatter, read it directly and render it as the pre-flight strip — do not re-derive from scratch. `membrane-controller` carries the first instance; not yet retrofitted to the other twelve skills." → *provenance* — nesi/mind/PROTOCOLS.md:503 verbatim

That line itself points to a provenance note the preflight manifest pass never opened. PROTOCOLS_PROVENANCE.md carries the fuller, dated account:

"The skills-wrapper meta-skill mechanism (built 2026-07-21, Kevin's mark — Branch 3 of the 2026-06-26 pre-flight session, held in the felt-read queue since): distinct from the behavioral rule above. A heavy skill may declare its own manifest fields as frontmatter metadata (`manifest: {do, touches, size}`) instead of the do/touches/size being freshly derived, in prose, every time that skill runs. When a skill file carries a `manifest:` block, read it directly and render it as the pre-flight strip — do not re-derive from scratch. `membrane-controller` (`nesi/bench/membrane-controller/skill.md`, mirrored vendor-side) carries the first instance, since every membrane crossing needs the same three lines every time. Not yet retrofitted to the other twelve skills — this is the mechanism proven on one exemplar, not a completed pass across all of `nesi/bench/`. Extending it to another skill means adding the same `manifest:` block to that skill's frontmatter, nothing more." — nesi/mind/PROTOCOLS_PROVENANCE.md:22 verbatim
This single line settles the "twelve" question. The provenance text names the scope explicitly: "not a completed pass across all of nesi/bench/" — the "other twelve skills" is a claim about the nesi/bench/ population specifically, never about .claude/skills/* at all. See the Relationship/Interface tab for the arithmetic this implies.

One clause in the provenance line is itself unconfirmed by this edge's own read: "mirrored vendor-side." No copy of membrane-controller exists anywhere under .claude/skills/ in this repository (confirmed by grep across the whole tree — the only two hits for the skill file itself are nesi/bench/membrane-controller/skill.md). Whatever "mirrored vendor-side" pointed to in 2026-07-21, it is not currently true of this checkout.

What "the other twelve skills" was actually counting, and what changed since.

The arithmetic PROTOCOLS_PROVENANCE.md:22 supports

The provenance line's own words — "not a completed pass across all of nesi/bench/" — say the population being counted is nesi/bench/, full stop, never .claude/skills/. If "the other twelve" is taken literally against that population: 1 (membrane-controller) + 12 (uncounted) = 13 skill files in nesi/bench/ at the time PROTOCOLS_PROVENANCE.md:22 was written (2026-07-21, per its own dated mark).

nesi/bench/ holds 14 skill files today. The arithmetic is off by exactly one file relative to what the 2026-07-21 line implies — consistent with one skill having been added to nesi/bench/ since that mark, most plausibly diamond, since it is the one file in the current 14 that itself already carries a manifest: block never narrated anywhere as a second retrofit.

This dating cannot be confirmed by git. The whole repository's tracked history begins at one commit, 2981dda, dated 2026-08-11, titled "Initial snapshot: staged open game development" — everything before that date, including both membrane-controller/skill.md and diamond/skill.md, entered version control simultaneously in that single squash commit. There is no git-derivable answer to "which of the two came first" or "was diamond present on 2026-07-21." The 2026-07-21 date is sourced only to the provenance file's own prose mark, not to any commit timestamp.

Why ".claude/skills/*" was never a candidate reading of "twelve"

.claude/skills/* holds 13 files today, none carrying a manifest: block — including membrane-controller, which does not exist at that path at all. A reading of "twelve" as ".claude/skills population minus membrane-controller" fails on the first fact: membrane-controller was never a member of that population to subtract from. This closes off a possible reading the preflight manifest left open without needing to guess at intent — it is ruled out by the file system directly.

Interface state

No instrument in either tools/ directory checks this population automatically or flags drift between PROTOCOLS.md's stated count and the live file count — this reconciliation was done by hand for this edge-file, once, and will go stale again the moment a 15th nesi/bench skill is added.

Limits

What this file does not settle.

Not a ruling

This file selects, quotes, and arranges what is on disk. It does not decide whether PROTOCOLS.md:503 should be corrected, whether diamond's manifest should be narrated as a second retrofit, or whether the "mirrored vendor-side" clause should be struck. Those are Kevin's calls, in his own words, per this corpus's own supersession convention (a mark on top, never a silent edit).

The 2026-07-21 date is a single unverified mark

It comes from PROTOCOLS_PROVENANCE.md's own prose, not from a commit timestamp. This edge could not independently confirm it, and could not confirm whether diamond/skill.md existed before, at, or after that date — the repository's history does not go back that far.

Frontmatter-only census

The manifest: grep checked for the literal frontmatter key. It does not check whether any skill's body prose describes an equivalent do/touches/size shape without using that exact YAML key — a looser reading might turn up more partial matches, but would depart from PROTOCOLS.md's own stated mechanism, which is specifically about the frontmatter key being machine-renderable without re-derivation.

No instrument enforces this reconciliation

Nothing in tools/ re-checks PROTOCOLS.md's stated count against the live file count. This edge-file is itself a snapshot, current as of 2026-08-27, and will drift the same way PROTOCOLS.md's own "twelve" already has.
