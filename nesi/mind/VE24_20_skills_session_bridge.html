What actually connects these two

Adjacency without ownership.

The mandate lives at the boot-path layer, not inside a skill

verbatim Root CLAUDE.md: "This is a session-level rule, not a daily-cycle step... producing this file is a create action, so it is required here, at the boot-path layer, rather than folded into that skill's close-out. daily-cycle's existing close-out (metabolize, snapshot, gauge, log line) is unchanged by this." This is the edge's central fact: the one skill positioned to plausibly own session-bridge production explicitly does not, by direct quote in the rule that created the mandate.

The checker is instrument-layer, not skill-layer

session_bridge_check.js lives in root tools/ alongside other whole-repo checks (e.g. tools/ledger.py), not inside any .claude/skills/ or nesi/bench/ directory. It has no SKILL.md of its own and is not one of the 27 counted in Group F.

Confirmed: never invoked automatically

instrument fact Grepped for session_bridge_check / SESSION_BRIDGE across nesi/game2d/tools/check_all.js and everywhere under nesi/game2d/gate/ (which runs gate.mjs) — zero matches in both. A separate whole-repo grep for the string session_bridge across every .js file in the project finds exactly one hit: the checker script itself. Nothing calls it. It runs only when a person types node tools/session_bridge_check.js by hand — the preflight's open question ("invoked automatically anywhere, or only ever run by hand?") resolves cleanly to hand-run only, no auto-invocation found anywhere in the repo.

The terminological echo goes one way

The format spec's own "Standard tabs" section names its per-output tabs "Gift 01, Gift 02..." — the same word the unrouted-gifts pipeline uses. Both worked Session Bridge instances use this naming (confirmed: SESSION_BRIDGE_2026-08-27...html's tabs run Gift 01 through Gift 05). This is a vocabulary echo between the format and the gift-pipeline (edge 24's subject), not evidence of a Skills↔Bridge relationship — no skill file uses "Gift" this way, and this is named here only so the two thin L-touching edges (20 and 24) aren't mistaken for covering the same ground.

What this file does not claim

Limits.

This file selects, arranges, and tags. It does not decide whether a skill should be built to own session-bridge production, does not rank the two domains, and does not declare any project state settled. Where the material was thin, the file stayed short rather than manufacturing depth — the preflight's own instruction for this specific edge.

The 27-file skill count and its casing note are reused from this build's own directory listing and cross-checked against edge 2's independently-derived figure; neither file re-verifies the other's every claim beyond that one shared number.

A later addition to any of the 27 skill files, or a new invocation site added to check_all.js or gate.mjs, would change this edge's central finding — it is dated to this build, not asserted as permanent.
