What this is

A single-file HTML shape for carrying one working session's authority whole.

Instead of writing a session's output as scattered files or a linear chat log, this format packs the whole session — the human's own words, what was inherited, what was derived, how it was checked, and how it connects to the surrounding project — into one self-contained, multi-tab, visually-navigable HTML file. Any model can read this document, learn the shape, and produce a new file in the same shape from its own session's material.

The core idea: one file = one session, fully legible on its own, with every claim inside it tagged for where it actually came from — verbatim user text, prior/inherited material, or new material derived this session — so a later reader never has to guess what's settled and what's proposed.
Layout

Sidebar + tabbed panels, all in one file.

Left sidebar (fixed, ~260-270px, sticky)

A brand block (small kicker label, title, one-line subtitle), a compact metadata box ("seal-mini") stating the no-network guarantee and any special notes, and a vertical list of tab buttons — one per section of the session.

Main area

A slim sticky topbar (breadcrumb + status dot), then one <section class="panel"> per tab. Only one panel has class active at a time; a small JS click-handler toggles it and updates the matching tab button's active class.

Everything inline

All CSS lives in one <style> block using CSS custom properties for color. All JS (tab switching, any diagram interaction) is one inline <script> at the end of <body>. No external stylesheets, fonts, or scripts — the file must open and work completely offline.

<div class="shell"> <aside>...brand + tab nav...</aside> <main> <div class="topbar">...</div> <section class="panel active" data-panel="overview">...</section> <section class="panel" data-panel="prompts">...</section> ...one section per tab... </main> </div> <script> document.querySelectorAll('.tabbtn').forEach(btn => btn.addEventListener('click', () => { document.querySelectorAll('.tabbtn,.panel').forEach(el => el.classList.remove('active')); btn.classList.add('active'); document.querySelector(`[data-panel="${btn.dataset.tab}"]`).classList.add('active'); })); </script>
Recurring content

The tab set that has repeated across every build so far.

Overview / Bridge

What the file is, a short metadata table, and (optional) an inline SVG diagram of how the pieces of this session relate to each other and to the wider project.

Prompts

The human's own messages, verbatim — typos and repetition kept, never paraphrased. Each block tagged verbatim · user.

Gift 01, Gift 02, ...

Each substantive piece of output this session produced, one per tab, with its own provenance tags on individual claims inside it.

Process

The actual steps taken to get from input to output — numbered, honest about dead ends, not a cleaned-up narrative.

Lens / Sources

What interpretive frame or prior material was drawn on, with collapsible (<details>) blocks holding the raw source text so a reader can check the quote against the source.

Relationships / Routes

How this session's output is proposed to connect to the rest of the project — each proposed connection tagged with a state: built, spec'd-not-built, dreamed, or open/no-route-yet.

This set is a starting menu, not a fixed schema — add or drop tabs to fit what the session actually contains. The only fixed rule is: Prompts stays verbatim, and every other tab stays traceable back to Prompts or to a named external source.

Styling

A consistent, theme-aware, warm-neutral visual system.

Color via CSS variables

Define a full palette on :root (background, surface, ink, muted text, hairline, and 3-4 accent hues each with a "soft" background variant), then override the same variable names inside @media(prefers-color-scheme:dark). Nothing hardcodes a color outside these tokens, so the whole document flips themes automatically.

:root{ --bg:#f4f1ea; --surface:#fffdf8; --ink:#181815; --muted:#6a685f; --line:#d8d2c4; --gold:#b28225; --gold-soft:#f1e5c9; --blue:#436a77; --blue-soft:#dfeaed; --red:#924d43; --red-soft:#f0dfdc; --green:#496b55; --green-soft:#dfebe2; } @media(prefers-color-scheme:dark){ :root{ /* same names, dark values */ } }

Reused component classes

.seal — a bordered metadata grid. .card / .route-card — a bordered content block. .keyline — a gold-accented pull-quote/callout. .code / .prompt — monospace verbatim blocks. .tag — small pill labels for provenance. .process — numbered step cards. Optional inline SVG (.mapbox/.mapnode/.wire) for a relationship diagram with hover/click highlighting.

Print support

A @media print block that hides the sidebar/topbar and forces every panel visible with a page break before each — so the same file can be printed or exported to PDF as a linear document.

The one rule that matters most

Tag every claim by where it actually came from.

This is what keeps the format honest — without it, a multi-tab document with a diagram just looks authoritative. The tags force a reader (human or model) to see at a glance what is settled fact, what is quoted, and what is this session's own proposal.

TagMeaning
verbatimExact quoted text from a named source — no paraphrase, no cleanup.
markedA decision or state that a specific person actually approved/selected, not inferred.
inheritedMaterial that existed before this session touched it — carried forward, not created here.
instrument factA fact produced by running a script/check/tool — reproducible, not asserted.
session-derivedNew reasoning or synthesis produced during this session — the part most likely to need checking later.
state: built / spec'd / dreamed / openFor any proposed connection to the wider project — how real is this connection right now?
Constraints that make the format trustworthy

What the file is not allowed to claim about itself.

No network, ever

Every byte a reader needs must already be in the file: inline CSS, inline JS, no CDN script tags, no Google Fonts, no external images by URL. This is what makes it truly portable between models, machines, and time.

It selects and arranges — it does not decide

The document may quote, juxtapose, diagram, and tag. It should explicitly disclaim any authority to canonize a claim, rank a person's choices, or declare a project state settled. State that limit somewhere visible (an overview-tab line works well).

No silent smoothing

Typos and rough phrasing in verbatim quotes stay as typed. Dead ends and mismatches found during the session get their own visible callout (a red/warning-colored block) rather than being edited away.

Reusable, not one-off

End the file with an explicit note that a later session may copy this tab structure and swap in its own content — that's what makes the shape a format instead of a one-time document.

For the model reading this

To build one of these from your own session, do this.

1 · Pick the tabs

Start from the standard set (Overview, Prompts, Gift(s), Process, Lens/Sources, Relationships/Routes). Drop or rename any that don't fit; add tabs for content types unique to your session.

2 · Copy the shell

Reuse the sidebar + topbar + tabbed-panels skeleton and the tab-switch script shown in the Structure tab — the mechanics don't need reinventing.

3 · Set your own palette

Keep the token structure (bg/surface/ink/muted/line + a few accents, each with a soft variant, light + dark) but the actual hex values are yours to choose.

4 · Fill Prompts first, verbatim

Paste the human's actual messages unedited. This tab is the anchor everything else in the file should trace back to.

5 · Tag as you write

As each other tab is filled in, mark every non-trivial claim with a provenance tag from the Provenance tab. If you can't tell which tag applies, that's a sign the claim needs to be checked before it's asserted.

6 · State the limit

Somewhere visible, say plainly what this file is not authorized to do (canonize, rank, declare final state) — don't let the polished look imply more authority than the content actually has.

7 · Verify it's actually self-contained

Open the finished file with no network connection. If anything fails to load or render, something external leaked in — fix it before calling the file done.
