2 · root gate/gate.py — a display-and-staging tool, never the closer

verbatim Its own header, read directly: "THE GATE — backend. One owned tool, Python standard library only... It STAGES and DISPLAYS. It never CLOSES. The mark happens off-panel, from the body, as an act; this tool only RECORDS that a mark already happened. There is, by law, no 'approve' verb." Four named laws enforced in code: GROUND (inlines a static HTML snapshot), NO-CLOSE (no deciding verb), DISPLACED-ZERO (validate() refuses to build if any item carries a score/verdict/recommendation), SUBTRACTION (nothing hard-deletes; compost is a status, not an erasure). CLI verbs: build, serve, daemon, stage, mark. This is a whole-repo-facing display/staging surface, architecturally distinct from both other systems — it renders a snapshot of marks made elsewhere, rather than running instruments of its own.

3 · nesi/nesi_bench_v0/gate.py + ledger.py — read in full this pass

instrument fact DORMANT · SELF-CONTAINED Located at nesi/nesi_bench_v0/ (the cross-cutting findings' path correction confirmed again this pass — not at DSS-root). gate.py, 118 lines, its own header read verbatim: "Stage 3 — the gate carry (v1 Sec 6, guardrails Sec D). Pure geometry only. No rendering, no DOM, no drag handling... The gate is not a button (guardrail #17-18): nothing here computes readiness, eligibility, or a 'ready to cross' signal." It defines five pure functions — gate_seam_x(), segment_crosses_vertical(), swept_box_crosses(), is_straddling(), resolve_crossing() — that answer one narrow geometric question each: did a dragged object's link cross a vertical seam between two named rects (gate and landing) during a pointer-driven carry, and does that ratify, sever, revert, or leave an edge unchanged. It is a collision-geometry module for a drag-and-drop UI region named "gate," not a builder's admit/refuse pipeline.

ledger.py, read in full

verbatim Its own header: "The dry-run gate ledger (v1 Sec 12, named as a v0 deliverable, built 2026-07-21). Python-side, stdlib-only persistence: record() appends one JSON line per mark-worthy event to nesi_bench_v0/ledger/dry_run.jsonl." Two functions: record(event, detail) appends one JSON line, no timestamp field by design ("this module has no clock primitive of its own... a caller that wants one passes it inside detail explicitly, so provenance is never silently invented here"); read_all() reads every entry back, treating an empty/missing ledger file as a true, unremarkable state rather than an error. verbatim Its own honest-limit line, read directly: "this module has no live call site yet. The rendered surface... is pure client-side JS with no server round-trip — there is no write path from a pointerup mark event back into this Python module today."
