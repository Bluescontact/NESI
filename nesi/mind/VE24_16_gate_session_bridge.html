What this edge is

Two mechanisms that both ask "did the session close correctly" — and do not speak to each other.

This edge sits between Group D (Gate/Ledger — nesi/game2d/gate/, its eight instruments, LEDGER.jsonl, MARKS.jsonl) and Group L (Session-bridge format — the format spec, two worked instances, and tools/session_bridge_check.js). Per the geometry of the vector equilibrium these are two of the twelve rule/format domains that touch by an edge, not by shared group membership. The preflight manifest's own SCOPE for this edge found no wiring between them and framed the finding plainly: "Two independent 'did the session close out correctly' mechanisms exist and do not talk to each other." Interface

How D and L actually stand right now — two closures, no cross-reference.

1 · Neither mechanism names the other

A grep for "session_bridge" / "SESSION_BRIDGE" across the whole nesi/game2d/gate/ tree returns zero matches, re-confirmed at this edge's build time exactly as the preflight found it. A grep for "gate" / "LEDGER" / "MARKS" inside session_bridge_check.js also returns nothing beyond its own comparison to refusal_check.js by name in a comment, which is a contrast, not a reference to game2d's actual gate files.

2 · Different jurisdictions, by their own stated words

gate.mjs declares itself "BUILDER'S GATE, not player's surface" — its scope is the game2d build's own mechanics (motion, self-use, blanks, subtraction, landing, magnitude, return, dispute). session_bridge_check.js's scope is the whole repository's session-closure discipline — it reads nesi/mind/ for bridge files and shells to git log for the most recent commit, with no reference to any single project's internal state.

3 · One structurally can refuse; the other structurally cannot

gate.mjs's exit codes (0/1/3) are read by check_all.js as part of a pass/fail suite — a refusal there is a real, actionable signal. session_bridge_check.js has no exit-code branch at all (confirmed above by direct grep and read, not merely by trusting its header) — even if a caller wanted to treat a detected gap as a failure, the script currently gives that caller nothing to check but its own stdout text.

4 · Neither is invoked by the other's runner

Confirmed by direct grep of check_all.js and gate.mjs: neither file contains any reference to session_bridge_check.js or to the string "session_bridge." The two mechanisms run independently, by hand, on separate commands, at whatever cadence a session chooses to run either one.

Stated as a finding, per this edge's own scope: this corpus currently has two separate, independently-functioning instruments that both answer some version of "did the session end the way it was supposed to," one hard-gating a build's own mechanics and appending to a builder ledger, the other soft-reporting on the whole repository's session-closure discipline with no ledger and no exit signal — and nothing today reads one in light of the other.
Open fork for Kevin, named and not resolved: the preflight manifest's own open question for this edge asked whether the edge-file should document the non-wiring only, or also propose how the two could connect. Per this task's explicit instruction, that second option is flagged here as an open fork only — should session_bridge_check.js's finding ever be surfaced through the game2d gate/ledger, or through check_all.js, or should the two mechanisms stay structurally separate because they answer genuinely different questions at genuinely different scopes (one project's build mechanics vs. the whole repo's session discipline)? This file takes no position on that fork and proposes no design — it is Kevin's to name, in his own words, if and when he wants it named.
