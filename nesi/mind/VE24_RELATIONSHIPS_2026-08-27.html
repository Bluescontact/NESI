What this document is

The 24 edges, read against each other.

Each of the 24 VE24 files was built and verified in isolation, one edge at a time. This pass reads them as a set: which findings corroborate, which depend on each other, which converge on the same underlying fact from different angles, and which gaps — held open in one file — turn out to already be closed by a sibling. Nothing here overrides any of the 24 files' own findings; where this document adds something, the source file gets the credit and the citation.

Two things were genuinely unresolved anywhere in the 24 files until this pass ran them against each other: whether two independently-discovered "twelve laws" citation trails (edge 1, edge 3) were the same historical system, and whether tools/boot_hook.py collides in name only with root CLAUDE.md's "THE BOOT PATH" section. Questions no single edge could answer alone

Two findings this swarm pass itself produced.

1 · The two "twelve laws" trails are the same system

Edge 1 (Laws↔Lenses) traced nesi.md's stale "Law 4" citation three hops back to the suspended vendor ~/.claude/CLAUDE.md's former twelve-laws section. Edge 3 (Laws↔game2d build) independently traced 8 of 10 law-citations in the live build's own code to a system refusal_check.js:8 names as "PROTOCOLS.md's twelve laws." Neither edge checked whether these were the same system. They are: nesi/mind/PROTOCOLS.md:3 states directly — "the NESI governing brief (the world, the twelve laws, the verification bar, the slice rule) now lives beneath the pointer" in the vendor CLAUDE.md, per a 2026-08-07 mark. Read against the vendor backup's actual "Laws that break the build if forgotten" section (lines 117–147, all twelve laws present), every one of refusal_check.js's named laws (2, 3, 4/5, 6, 11) matches word-for-word. One corpus-wide numbering system, referenced by two different pointer-names (the vendor file directly, or "PROTOCOLS.md's twelve laws" once removed) because the content physically moved in 2026-08-07 while PROTOCOLS.md kept conceptual ownership of it.

2 · tools/boot_hook.py is not a naming collision with CLAUDE.md's "THE BOOT PATH"

Edge 22 (Tools↔Library) flagged this as an unread, unresolved possible collision. Read directly: tools/boot_hook.py's own header states its purpose exactly — "CLAUDE.md routes LEARNED.md by asking a session to read it, which leaves the reading to judgement. This hook reads the file and puts the laws in context before the session's first thought, every time." Not a collision — this is the filesystem-fact mechanism implementing what CLAUDE.md's "THE BOOT PATH" section states in prose. One system, two layers (instruction and enforcement), same name for a reason.
