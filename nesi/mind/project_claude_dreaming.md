"Claude dreaming" — Kevin's term for autonomous overnight agent work that composts the existing library into shareable, published open-source artifacts. This is the gift infrastructure at personal scale: not productivity automation, but deployment of substrate that already exists.

**Why**: The library is dense. The manuscript ([[project_architecture_of_coherence]]) names itself mid-succession; the kit ([[project_ri_kit]]) is mid-build; the source library and patterns docs ([[project_source_library_and_patterns]]) are canonical but underexposed. The bottleneck is Architecture/Circulation — deposit and propagation. Dreaming is the agent layer that handles that without consuming Kevin's daily presence.

**How to apply (the structural constraints)**:
- **Substrate-first sequence** (Chapter 10.7 of the manuscript): the dreaming agents are Phase III work. They deposit from genuine exchange Kevin has already produced. They do NOT generate the substrate, and any attempt to use them to substitute for substrate produces the CouchSurfing failure mode. See [[feedback_substrate_before_artifact]].
- **Voice preservation**: PATTERNS_AND_VOICE ([[project_source_library_and_patterns]]) is the reference. Dreaming agents must not flatten the direct/geometric register into LinkedIn voice. See [[feedback_voice]] and [[feedback_demonstrate_not_describe]].
- **Never publishes autonomously**: agents stage outputs for Kevin's review. Publication is a human move. Differentiation stays with Kevin.
- **Gift form, not extraction**: the dreaming serves circulation of work Kevin would gift anyway — not optimization for reach, engagement, or transactional outcome. See [[project_osg_personal_scale_frame]] and [[feedback_collaboration_gift_form]].
- **Surfacing, not demanding**: morning output names what composted, what staged, what couldn't classify. Never produces a to-do list. If it does, the geometry has been inverted.

**Operational shape** (target, not yet built):
- Library locations + classification scheme (kit-internal / library-internal / public-shareable / archive / noise)
- Staging folders: `/inbox/` (Kevin drops in), `/composted/` (agent has classified), `/staged/` (ready for review), `/published/` (Kevin has released)
- Nightly composter: reads inbox + recent library changes, runs the register audit ([[project_register_audit]]) on each, files appropriately, drafts shareable versions for staged items
- Morning artifact: one paragraph naming what surfaced
- Weekly weaver (Phase III+): cross-links recent material with older patterns
- Eventually: publication targets (OSG site v3, GitHub repo for the kit, Notion workspace for the library)

**Current state**: Vision named. Substrate-staging not yet built. First concrete move is the staging architecture (folders, classification scheme, review ritual), not the agents themselves. The agents come after the staging proves it can hold them.
