The mandate, verbatim

**Added 2026-08-27 on Kevin's mark:** "i want the session bridge html wired as the mandatory return in a session. it keeps the work inside of a session cleanly bounded, and transferable." **Every session ends by producing one Session Bridge HTML file.** The shape is specified in full, self-demonstrating, at `nesi/mind/FORMAT_SPEC_2026-08-25_session_bridge_html.html` — read it before building the first one. A worked example exists at `nesi/mind/SESSION_BRIDGE_2026-08-25_build_state_survey.html`. Write the new file to `nesi/mind/SESSION_BRIDGE__.html`, one file per session, self-contained (no network, no CDN, works offline), tabs at minimum: Overview, Prompts (verbatim, untouched), one tab per substantive piece of output, Process, and Sources — with every non-trivial claim carrying a provenance tag per the spec's Provenance tab.

Interface

How B and L actually connect right now.

1 · The rule lives in B, points at L

CLAUDE.md (Group B) does not define the format itself — it delegates entirely to the spec file (Group L) with "read it before building the first one," and names the checker (also Group L) as the mechanism that verifies compliance. B is the authority that requires; L is the shape and the instrument that checks.

2 · The checker closes the loop, but doesn't enforce it

tools/session_bridge_check.js sits at repo root, outside both nesi/mind/ (where the spec and instances live) and any per-project gate (game2d's gate.mjs, which this checker explicitly contrasts itself against). It reports; it does not refuse. State: built as a report-only instrument — never spec'd or intended as a hard gate.

3 · The daily-cycle boundary is a deliberate seam, not a gap

CLAUDE.md's text gives the actual reason for keeping session-bridge production out of daily-cycle: that skill's own governing rule ("it invokes, never creates") would be broken by folding a create-action into its close-out. The boundary is load-bearing on a different skill's law, not arbitrary.

4 · Both real instances confirm the loop currently works

Two Session Bridge files exist, both post-date the format spec, both were produced under the mandate window (2026-08-25 predates the mandate's own CLAUDE.md addition by two days — meaning the format existed and was already in worked use before the rule requiring it was formally written into CLAUDE.md on 2026-08-27), and the checker confirms no tracked change currently outpaces the newest one.

Read plainly: this is one of the few edges in the VE24 set where rule (B) and format (L) are not just adjacent but actively closing a loop on each other in real time — the mandate names the spec, the spec's own instances predate and now follow the mandate, and the checker was built the same day as the mandate to confirm the loop holds.
