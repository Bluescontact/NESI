## Stage-0 zeros (all open, all Kevin-held)

1. **Threshold line** — one sentence from Kevin's body; speaks to visitor's felt condition; does not instruct. If it fails, the build fails — it is the only part that cannot be iterated post-launch.
2. **Node content — four faces, self-authored** — Self (carries/needs/refuses), Field (named ground), Routes (how he moves), System (what holds him). The refuses line is hardest and most load-bearing.
3. **Governor/membrane boundary** — Kevin names what stays inside (THE GOVERNOR, CONVERGER, direction instruments, DISPATCHER, negative workspace) vs. what the site surface carries.
4. **Second node decision** — one of three marks: (a) Kevin's node only + honest empty slot, (b) real second person consented + node content supplied, (c) stated 'forming' state with explicit language.

---

## Three irreducible differentiators

1. **Threshold line as load-bearing joint** — redistributes the weight of explanation into one sentence; cannot be improved after first visitors arrive; only part that cannot be iterated post-launch.
2. **Structural incapacity as trust instrument** — missing fields (no amount, no recipient, no decline log, no role, no claim) make debt unrepresentable; schema enforces what language only asserts; adding any tracking field collapses the frame.
3. **Kevin-as-node at structural parity** — same component, same field count, same interaction model as any visitor node; inhabitation proof requires real, current, specific data — not polished/evergreen; this requirement is ongoing not one-time.

Minimum viable close: Kevin's contact in Zone 3 as a plain direct line — visitor populates their node, sees Kevin's node, knows how to reach him. Must be named in the spec, not left implicit.
