Standing record · 2026-08-25

What a build-state survey of this corpus establishes

This record documents the standing state of a browser-game build as its own files report it, and the survey method that produced that reading. It decides nothing: every state tag reports what a project file already says about itself. No fork is ruled, no candidate ratified, no verdict of finished or unfinished issued.

The standing state it establishes

Built mechanism coexists with named, unresolved contradictions.The headline pattern: real wired mechanism (12 of 24 progression edges code-confirmed built; a 9-instrument gate suite running and logging; a 24-level content library begun) stands alongside contradictory boot instructions, a retracted verification claim, and repeated non-passing gate verdicts. Neither half is smoothed into the other.
Progression.24 levels map to the 24 edges of a cuboctahedron (12 vertices, 4 hexagonal circuits). 12 edges are built by direct code read. An earlier "verified live" citation for those 12 was later retracted because the walk it cited was never witnessed under the corpus's own standard — a code-confirmed build and a witnessed walk are distinct states, and the record keeps them distinct.
Content vs. wiring.The first four levels are mechanically wired, but the text beat — what the player actually writes — is marked not-yet-written for all four. A named pacing problem (the mechanic does not fill the target session length) stands unresolved. "Wired" and "authored" are separate states.
Verification ceiling.The last full verification pass walked all 12 built seats by an automated hand and returned UNWITNESSED — rendering without crash, one full seam walked with real persisted state, but no independent human witness. The verdict names its own limit rather than upgrading itself.
The infrastructure gap.The gap toward bootable personal infrastructure is stated in one line in the corpus: everything exists in three places that do not know about each other, and none of it leaves the browser. Export/import off browser-local storage ("the node is a file") is named the largest single gap.
Instrument suite.The runner covers 16 node instruments plus one ESM instrument and one gate entry, with three in-page instruments outside its coverage; older instruments are retired to a named directory rather than deleted. The gate ledger's three most recent runs all returned an identical vacuous verdict — reported, not interpreted, because it bears directly on any claim of finished.

The collision pattern it establishes

The survey's lasting finding is less any single fact than a recurring shape: the corpus's own records disagree with each other, and the correct handling is to name each collision where found rather than pick a side.

Two same-day boot files give contradictory instructions (read the corpus first vs. do not), and neither carries a mark. Both stand; the collision stands with them.
Two vision documents remain live in parallel — a later rearticulation did not formally retire the earlier file; they carry different counts and different open-fork framing.
A decisions file's header contradicts its body — the header says the file can be composted entirely, yet the body keeps two items explicitly OPEN. Kept whole, contradiction visible.
A coverage file is superseded by its own top notice — the body below the notice is stale by the file's own admission, and stays as history under the notice.
A design-law collision is "closed" only by an unratified swarm — a swarm-decided resolution file claims to close it, but that file's own header says swarm-decided is not marked. The collision therefore remains open until a mark exists.
Compaction is recorded as storage, not loss.A 5,105-line build history was compacted to a pointer, the full text kept byte-for-byte in a named backup — a storage change described as such, distinct from a contested collision.

Routes to "finished," tagged by how real the connection is

State vocabulary.The survey uses a small honest ladder — built, unwitnessed · spec'd, not built · built, flagged · dreamed · open · spec'd, not marked — so that no item claims more state than its own file grants it. Candidate resolutions computed by agents stay candidate-only until each line carries a mark.

The method it establishes

Read the files directly, not from memory — every claim cites its file and approximate location; nothing is asserted from recall of the project.
Check scope before building — the survey's scope was chosen from explicitly offered options, not assumed.
Keep contradictions visible — where two files disagree, or a header contradicts its body, the disagreement is itself the finding (the divergence-is-held law applied to documents).
Declare what the pass did not do — levels not walked, the runner not re-run, backups not fully read — as open follow-ups, not claims.
The document limits itself in writing — it selects, arranges, and cites; it does not decide, smooth, or rank; it is self-contained with zero network dependencies; its structure is reusable by later surveys without inventing new mechanics.

Instance-level content — verbatim asks, per-session narration, and names — remains in the source corpus and does not cross.
