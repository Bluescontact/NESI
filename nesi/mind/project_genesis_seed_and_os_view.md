Two new artifacts at the DSS content root that future sessions must know about before building anything new:

- `Genesis Seed/` — composting workspace inside the Library facet. Substrate-staging architecture: items enter, get processed across cycles by the composter agent, surface as exemplars when dense enough. Six exemplars seeded (manuscript, Regulatory Aikido, Consent Architecture, Essence of the Gift, Pattern Library v1, OSG v3, recognition-infrastructure-repo, bus build, biochar toilet, nested can v1, HTML exemplar set). Daily rhythm is silent — agent only surfaces on attention-needed. Handoff doc at `Genesis Seed/SESSION_HANDOFF.md` carries the full state forward.
- `OS.html` at the DSS content root — visual render of `_PERSONAL_OS.md`. Four facets (Library / OSG / Personal Governance Model / RI Kit) with the somatic ground beneath (bus, biochar, bus essay) and the eleven refused extractions visible as a wall. This is the infrastructure view, not a page-for-others.

**Why:** Genesis Seed went through a reframe during the build — it was first conceived as a content funnel, corrected to substrate-staging architecture inside the Library facet. OS.html came out of that correction: needed a visual to hold the whole infrastructure so future framing mistakes don't recur. See [[tools-not-pages]] for the related discipline that emerged from the same session.

**How to apply:** Before starting any new work in the DSS content directory, open `OS.html` to orient in the infrastructure, and check `Genesis Seed/SESSION_HANDOFF.md` for the priority queue. Don't rebuild what's already staged. New library items go through Genesis Seed; don't dump them at the root. Tools for OSG go in `tools/` (first one: `tools/quick_diagnostic.html`), not as new pages.
