Why this replaced the tabbed-JS format

ORIGINchosen 2026-08-31, Kevin Mears — Option A of OPTIONS_2026-08-31_html_protocol.html
REPLACESFORMAT_SPEC_2026-08-25_session_bridge_html.html (kept whole, superseded, not deleted)
DEPENDENCIESzero — no CDN, no network fonts, no JavaScript anywhere
WHYthe JS tab-click mechanism was unclickable in at least one real viewing context
WHAT CHANGEDhide/show panels → one continuous scroll; tab buttons → anchor links
WHAT DIDN'Tthe visual system (tokens, cards, tags, tables) carries over almost unchanged
The core reasoning: a <a href="#section"> jumping to an id is native browser behavior with no dependency on script execution at all — the single most universally-supported interaction in HTML. If a viewer can render text and links, this format works in it.

Layout

Header

A kicker label, a title, a one-line lede. No sidebar — everything lives in the normal document flow, top to bottom.

Sticky jump-nav

A single horizontal row of pill-shaped anchor links, one per section, pinned to the top of the viewport as the reader scrolls. This is the entire navigation mechanism — no JavaScript, no toggled classes, no :target CSS trick.

Sections, all present, all at once

Every <section id="..."> is in the DOM and visible by default. Nothing is hidden and then revealed — the format's entire simplicity comes from not needing a show/hide mechanism at all.

<div class="wrap"> <header>...kicker + title + lede...</header> <nav class="jump"> <a href="#overview">Overview</a> <a href="#prompts">Prompts</a> ...one link per section... </nav> <section id="overview">...</section> <section id="prompts">...</section> ...one section per topic... <footer>...the limit statement...</footer> </div> <!-- no <script> tag anywhere in the file -->

The section set that carries over from the old format

Overview

What the file is, a short metadata table (.seal), and the one-sentence core idea.

Prompts

The human's own messages, verbatim — typos and repetition kept, never paraphrased. Tagged verbatim · user.

Gift 01, Gift 02, ...

Each substantive piece of output, one section per gift, with its own provenance tags on individual claims.

Process

The actual steps taken — numbered, honest about dead ends.

Sources

What prior material was drawn on — quote the file, not the memory of it.

Routes / Limits

What this file is and isn't authorized to claim, and what's still open.

Same rule as before: this is a starting menu, not a fixed schema. Prompts stays verbatim, and every other section stays traceable back to Prompts or a named external source.

Styling — unchanged from the old spec, on purpose

The tab-click failure was in the navigation mechanism, not the visual language. Every token, card, and tag style below is a direct carry-over.

:root{ --bg:#f4f1ea; --surface:#fffdf8; --ink:#181815; --muted:#6a685f; --line:#d8d2c4; --gold:#b28225; --gold-soft:#f1e5c9; --blue:#436a77; --blue-soft:#dfeaed; --red:#924d43; --red-soft:#f0dfdc; --green:#496b55; --green-soft:#dfebe2; } @media(prefers-color-scheme:dark){ :root{ /* same names, dark values */ } }

Reused component classes

.seal, .card, .keyline, .code, .tag, .process, table — identical to the old spec. Only .shell/aside/.tabbtn/.panel are gone, replaced by .wrap/nav.jump/plain section.

Print support

Simpler than before: the sticky nav just hides in @media print, and the page already reads linearly top-to-bottom — no forced page-breaks or panel-visibility overrides needed, because nothing was ever hidden.

Constraints, carried forward from the old spec unchanged

No network, ever

Inline CSS only. No CDN, no fonts, no external images. Now stronger than before: no JavaScript at all, so there's nothing to fail to execute either.

It selects and arranges — it does not decide

Same limit as before, state it somewhere visible.

No silent smoothing

Typos in verbatim quotes stay as typed. Dead ends get their own visible callout.

Reusable, not one-off

End with a note that a later session may copy this shape and swap in its own content.

For the model reading this

1 · Pick the sections

Start from the standard set. Drop or rename freely.

2 · Copy the shell

Header, sticky nav.jump of anchor links, then one <section id="..."> per topic. No script block at all.

3 · Set your own palette

Same token structure, your own hex values.

4 · Fill Prompts first, verbatim

The anchor everything else traces back to.

5 · Tag as you write

Every non-trivial claim gets a provenance tag.

6 · State the limit

Say plainly what the file isn't authorized to do.

7 · Verify by reading the raw file

Grep the finished file for <script — it should return zero matches. If it does, something crept back in that the whole point of this format was to remove.

This file selects and arranges. It does not decide, canonize, or rank anything on its own. A later session may copy this shape and swap in its own content — that's what makes it a format.
