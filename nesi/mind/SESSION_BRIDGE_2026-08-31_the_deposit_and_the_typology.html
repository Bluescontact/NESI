Phase 1

The deposit repo: archive, scaffold, first pipeline.

Kevin named an existing private repo, Bluescontact/NESI, already at that name — one commit, a README, 82K total. Rather than pick a different name or delete it, the plan was to archive it whole, then reuse it. Cloned in full (history included, not a snapshot) to nesi_repo_archive_2026-08-30/, still on disk, untouched since.

Scaffold v1 — wholesale copy

First pass: game/ = all of nesi/game2d, knowledge/ = all of nesi/mind. Simple, but not what "deposit" turned out to mean.

The pipeline, named

Kevin: "phase transition, metachrysalis/mycelium colonization process through pattern, and recognition capacity." Translated to filesystem terms: recognition = the gate's real admission ledger (MARKS.jsonl), not a session's own say-so.

tools/build_deposit.js v1

Three buckets, derived every run, never hand-sorted: game (traced from what index.html actually <script src>'s — turned out to be just index.html + solid.js), patterns (anything with a real gate admission), compost (everything else, kept whole).

A real bug, found and fixed

The "at" paths in MARKS.jsonl are relative to gate/ (where admit.mjs runs), not to game2d/ root. First version resolved them wrong — day_one.html and all three session-bridge files were silently landing in compost despite being genuinely admitted. Fixed by resolving against path.join(GAME2D,'gate') instead.

Verified, not assumed

Opened game/index.html from the deposit folder directly in the browser pane — confirmed it rendered correctly standalone, twice, before treating the game bucket as done.

Pushed

Force-pushed to Bluescontact/NESI (unrelated history to the old README-only commit, exactly why the archive step existed). GitHub Pages requested — blocked: Pages needs a public repo on this plan, and the repo was private with real compost in it. Held there rather than making it public with compost still inside.

Phase 2

The public split: no compost, tributaries, Pages goes live.

Kevin's correction: the public deposit must carry only the derived load-bearing material — gifts, relationships, nutrients — never the raw compost, and it should show where each gift's capacity actually came from ("tributaries").

tools/build_deposit_public.js

Same recognition signal as the private pipeline, three differences: no compost folder at all (unpromoted material is left out, not copied anywhere); inbox/ (gift cards, lens reports) joins gate/ and tools/ as a carried-whole mechanism dir; a new TRIBUTARIES.json.

TRIBUTARIES.json

Every admitted mark traced back to its own gift card or session bridge, plus (for gifts) the named in-repo sibling trees tools/library_lens.js scans for unrouted capacity — named, not republished.

A second bug, same root cause

The gift-card correlation regex was too strict (matched on id AND slug); loosened to match on the gift number alone after finding gift 13's id-slug ("burn_shape3_test") genuinely didn't match its own card's filename slug ("the_burn") — same gift, different word choice, not a bug in the data.

Force-pushed, made public, Pages verified live

Both actions blocked by the auto-mode permission classifier and confirmed with Kevin explicitly before proceeding. gh api repos/Bluescontact/NESI/pages/builds/latest polled until status:"built"; the live game opened at https://bluescontact.github.io/NESI/game/index.html and its page text read back to confirm it rendered — not just that the build succeeded.

Phase 3

"The whole directory is gone" — a real scare, a real resolution.

Mid-session, a routine ls before a git command showed the entire working directory reduced to a single folder — no nesi/, no .git, no CLAUDE.md, nothing from the deposit work. Verified independently via PowerShell Get-ChildItem and direct Test-Path checks against five specific known files — all False. Not a stale listing.

Ruled out first

Reviewed every command run this session: no rm -rf, no git clean/reset --hard against the repo root, every rmrf() in the pipeline scoped to nesi_deposit/ subfolders only. Nothing this session did explained a blast radius that large.

Investigated, not panicked

Checked the Windows Recycle Bin (228 items, none matching), checked for a renamed sibling folder on the Desktop, checked the OneDrive process was running. Reported findings plainly to Kevin and stopped all further writes pending his input — the correct response to irreversible-looking data loss neither caused nor understood.

Resolved

Kevin: "now C:\Users\KMEAR\dev\DSS content". The folder had moved, out of OneDrive into a local dev path. Verified via git log, file listing, and directly reopening game/index.html in the browser — everything intact, including full git history.

The cost

nesi_deposit_public/ and two just-written files (tools/deposit_lib.js, and the fix to the gift-card regex) hadn't made the move — regenerated and re-fixed at the new path rather than assumed identical.
