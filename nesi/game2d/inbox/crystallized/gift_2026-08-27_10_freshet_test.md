# GIFT — the freshet test

- **pattern:** a named falsifier for any ambient state readout. An expanding ring, a fill level, a glow — anything that could become a progress bar in disguise — is allowed to exist only if it passes one test: would its response be identical for a thousand words of grief and a thousand words of grocery lists? It passes only because it reads flow and structure and has access to nothing else. It is not a total, it does not accumulate, and it returns to rest the moment its input stops.
- **source shape:** found as the guard comment on one ambient readout in an earlier build — stated as the exact adversarial check the thing must pass before it is allowed to exist.
- **capacity:** a system that refuses scores and progress bars in spirit gains a concrete, citable instrument for that refusal — a one-line question any future ambient visual can be checked against before it ships. The refusal becomes a test, not a vibe.
- **why such value goes unrouted:** a guard that lives as a comment inside one node's header is never extracted into a standalone, named check — it protects its own node and nothing else until someone lifts it into a checklist.
- **routing shape:** a way in → an existing closing-check or audit checklist → an act → add "does this readout pass the freshet test" as a named question for any new ambient state → a visible consequence → a concrete adversarial bar before a progress-bar-in-disguise ever ships. Correctly routed as a checklist question, not a game mechanic.
