## What's being laid beside what
Stage 1 found the primary attachment point is `nesi/bench/composer/composer.py` (built, wired, unmarked), not the widget-layer chassis alone. This stage lays that pipeline beside the four things the cycle brief named: ARTIFACT_GRAMMAR, the bench objects it renders, ORGAN_CONTEXT, and THE_ASSEMBLY's tensegrity/organism geometry.

### 1. composer.py's register IS ARTIFACT_GRAMMAR's artifact rules, already rendered
ARTIFACT_GRAMMAR.md §2 states six rules every document must carry: status line, provenance, mark-reasoning inline, verdicts with conditions, falsifiers, no self-ratification. `composer.py`'s `REGISTER_CSS` and its three render functions (`render_card`, `render_infographic`, `render_doc`) implement these as literal CSS classes and template slots: `.status-line` (`_status_line()` — "STAGED — awaiting Kevin's mark" or the verdict, uppercased), `.provenance` (engine + dsl source), `.falsifier` (doc's closing line: "this document describes itself as rendered, not decided"). This is not an analogy — the grammar's textual law and the Composer's visual register are the same rule stated twice, once in words, once in code. Coupling point: solid, already built, no gap to close.

### 2. Bench objects (nesi/staged/*.json) are the material, already flowing through
`bench.compose_preview()` runs on every new object, `bench.land()` on every landed one — confirmed live-wired (Stage 1, section A). Sampled `nesi/staged/2026-07-19_made_id_like_to_build_a_lease_3e1350.json` and neighbors: each staged object already carries `bench.intent`, `object.summary`, `object.items[]`, `engine`, and (per the wiring) a `composed` block with `card_html`/`infographic_svg`/`doc_html`/`diagram_status`. This is the exact shape a "living space" of nodes would draw from — no new data model needed to seat one object as one node; the gap is entirely on the arrangement/interaction side, not the data side.

### 3. composer.py's DSL edge-kinds ARE THE_ASSEMBLY's cable-net, already typed
THE_ASSEMBLY.html names the tensegrity reading precisely: patterns as rigid discontinuous compression members, *stated tensions* as the cable net ("a tensegrity structure cut one cable and the whole thing slumps while every strut stays intact"), falsifiers as pre-tensioned cables that fail loud, integrity in the coupling rather than any member. `composer.py`'s diagram DSL already has a four-kind typed edge grammar drawn as distinct dash patterns — `drain` (4,3), `feed` (solid), `loop` (2,3), `block` (1,3 + a block-tick) — plus a `leverage.on` marker for "the one move." This is a real, already-coded vocabulary for exactly the kind of stated-tension cable net THE_ASSEMBLY describes in prose. Coupling point: the renderer that would draw a reorganizing node-space already has a typed edge language sitting one level below "generic box-and-arrow" — Stage 3 doesn't need to invent an edge grammar, only decide whether *bench-object-to-bench-object* relations (not just node-to-node inside one object's diagram) map onto these same four kinds or need their own.

### 4. ORGAN_CONTEXT's laws bound the space, and composer.py already honors them
"Staging only," "never read the writer," "no mood tracking / no reflection of inner state back at Kevin" — composer.py's default status line is `STAGED — awaiting Kevin's mark`, never a verdict it invents, and it renders only operational content (summary, items, diagram) — no sentiment, no writer-state slot exists anywhere in `REGISTER_CSS` or the three render functions. No violation found; the existing organ is already law-abiding. This matters for Stage 3: the living space can be spatial and reorganizing without needing new guardrails — the render layer's discipline is already in place, it just doesn't yet cover *many objects at once*, only one object's own diagram.

### 5. The actual gap, named precisely (carried from Stage 1, sharpened here)
Composer draws ONE object's diagram (a handful of nodes inside that object's own DSL) at a fixed scale (`card`/`full`). It has never drawn a space where MULTIPLE bench objects sit as nodes relative to each other, are movable, prunable, or reorganize on interaction. The chassis v4 click-mechanics (open/steer) have likewise never wrapped a composer-rendered artifact — every chassis card in use today (including this cycle's own widgets) carries hand-authored plain-language text, never a `composer.compose()` output embedded inside a card body. The two built things have not yet touched each other, and neither one, alone, is the living space — that's genuinely Stage 3's work, not something to backfill here.
