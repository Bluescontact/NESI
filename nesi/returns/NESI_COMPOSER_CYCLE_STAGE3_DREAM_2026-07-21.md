# COMPOSER CYCLE — STAGE 3 DREAM
**Date:** 2026-07-21. **Ground:** Stage 2 GATHER (composer.py's register/DSL/edge-kinds, staged bench objects, THE_ASSEMBLY's tensegrity read, ORGAN_CONTEXT's laws). **Status:** generative only. Nothing below is built, developed, or ratified. This file places the dream; the membrane at its close is Kevin's alone.

## Starting from the interaction, not the widgets
Not "what primitives do we have, how do we arrange them" — what would it feel like to open this and work in it. One room. Kevin looks at it the way he looks at the gate today: from outside, not as a character inside it (THE_ASSEMBLY's own law — "a tensegrity structure has no operator... Kevin stands outside it at the gate, and the whole design exists to keep it that way"). No avatar, no first-person walk-through. A console, not a game world. Consistent with nesi_app.py's own standing mark: "the surface becomes a true native window, no web layer."

## The space
One continuous plane, panned and zoomed, never paginated into tabs. Named boundary bands sit in it — roughly gate_data's own vocabulary (staged / held / canon / compost) — each rendered with composer.py's existing boundary-band primitive: a hairline rectangle, drawn first, largest, most persistent, exactly as the symbol law already requires inside a single diagram today. The dream does nothing but let that one primitive hold multiple bands side by side instead of one band per isolated diagram.

Inside each band, nodes: one per bench/pattern object, and a node's body is not a new invented icon — it is **composer.compose(obj)'s own "card" render**, unmodified register, sitting at its natural size. This is the literal answer to "how does the grammar render into geometry": it already does, at the single-object scale; the dream is letting many of those already-correct renders sit in one room instead of one at a time.

## Edges — reusing the DSL's four kinds, not inventing a fifth
`composer.py`'s dash-kinds (`drain`, `feed`, `loop`, `block`) currently draw relations *inside* one object's own hand-authored diagram. The dream repurposes them for *inter-object* relations, unchanged in rendering:
- **feed** (solid) — a pattern EXTENDS another; a bench object's intent cites a prior one. Direction of build.
- **loop** (short dash) — a HELD item's cable curls back to its own named re-screen condition, rather than floating as a text tag beside it. The condition *is* the cable.
- **drain** (medium dash) — lineage into compost; a fading, one-directional line toward a ghosted node, not a severed one.
- **block** (fine dash + tick) — an explicit veto or a falsifier that killed a claim; the tick-mark THE_ASSEMBLY's own falsifier language already implies ("snapping is designed to be loud").

No fifth kind is proposed. If the space ever seems to need one, that is a signal to look harder at these four before adding a style branch — composer's own invariance law ("if you find yourself adding a per-item style branch here, stop") applies at the room scale exactly as it applies at the single-diagram scale today.

## Tensegrity as literal mechanics, not metaphor
Nodes are the rigid, discontinuous compression members — composer's own invariance rule already forbids a node from deforming or varying by item (no per-item layout/color), so "rigid" costs nothing new to build. Edges are the cable net; a **snapped cable** — a `feed` edge whose target has been composted, a `loop` whose condition can never resolve — is rendered exactly as-is: the node stays, intact, fully rendered, while its cable simply isn't there. THE_ASSEMBLY names this precisely as tensegrity's own diagnostic power: "cut one cable and the whole thing slumps while every strut stays intact... the named dominant failure mode is edges dying while vertices hold." The dreamed space makes that failure mode visible by construction, not by a separate audit script.

## Reorganizing, tending, pruning
Auto-layout — spacing nodes within a band by count or by shared-edge density (Obsidian's move: nodes with more shared feed-edges sit nearer each other) — is rendering, always-on, and never a mark; it is the same "invariance enforced by the renderer" already governing single diagrams. **Dragging a node within its own band is free** — it's the room tending itself for legibility, no different from picking the resting layout composer already computes.

**Dragging a node across a boundary band is not free.** Per ORGAN_CONTEXT's first law ("the run stages; it never marks") and the organism's own constitution (no self-directed growth, `enqueue` structurally unavailable — "a job cannot author a job... the bench cannot grow itself"), a cross-band drag can only ever *propose*. Committing it routes through the exact mechanism already built and just fixed in this cycle's own widget: the chassis's heavy-card manifest (three plain lines — I'll / it touches / how big — then a real GO). Dragging a node from staged into canon is, mechanically, the same gesture as clicking a heavy card's GO today; the space doesn't invent a new consent mechanism, it spatializes the one already standing.

## The grammar, rendered as geometry, word by word
- **mark** → the one event that actually moves a node across a band, committed through the manifest gate, logged like any other mark.
- **stage** → a node sitting inside a band, inert, fully rendered, awaiting that event.
- **cross / the membrane** → the animated pass of a node from one band into the next, fired only by that committed drag — never automatic, never batched.
- **compost** → a node fading to a low-opacity, lineage-only render inside a compost band at the room's edge — present, never deleted, exactly as compost already means today.
- **HOLD** → a node with a `loop` cable curling to its own condition — the condition rendered as the cable's own path, not a floating label.
- **canon / patterns** → the largest band, the flat reference plane other bands' cables most often anchor into.
- **the gate** → the one seam every node must cross through to leave staged and enter canon — one named seam in the room, not a door per pattern.
- **felt-read** → renders nowhere. No node, band, or cable encodes Kevin's felt-read; no mood-color, no confidence-shading, on purpose, matching the standing rule that a blank felt-read field is already a complete record.

## The space's laws, flatly stated
1. One room, continuous, pan/zoom — never tabs, never pagination.
2. A node's body is composer's own unmodified card render — zero new visual vocabulary for what a node looks like.
3. Edges are the DSL's four existing dash-kinds, repointed at inter-object relations — no fifth kind without first proving these four insufficient.
4. Bands are the existing boundary-band primitive, one per named zone, flat ink only — color never carries meaning, at the room scale exactly as at the diagram scale.
5. In-band repositioning is free, always-on rendering. Cross-band movement is proposal-only until the existing heavy-manifest GO commits it as a real, logged mark.
6. Kevin views from outside; no avatar, no first-person traversal. The space cannot rearrange its own bands or invent a new one — that is the organism's own refused capacity (no self-directed growth), not a missing feature.
7. A snapped cable (composted or unresolved target) renders exactly as itself — node intact, cable simply absent. The mismatch is the diagnostic, never smoothed into a warning icon or hidden.
8. Felt-read renders nowhere, ever.

## Falsifier for this dream itself
If building this space ever seems to require composer.py to grow a fifth edge-kind, a per-item color, or any style branch beyond what already exists to make the room "read" — the dream broke the invariance law it claimed to extend. The fix in that moment is a plainer space, not a looser register.
