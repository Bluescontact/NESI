GIFT — site it on the grain, never by hand

  • pattern: a placement derived entirely from the data's own shape — the highest standing point, the steepest descent from it, the narrowest cross-section along that course — with zero authored coordinates anywhere. Nothing placed by hand: every position is read off the underlying structure, so if the canon changes, the placement moves with it.
  • source shape: built in an earlier build's terrain system, siting a river and a dam off the ground's own grain.
  • capacity: any feature that needs to site something new (a gate, a marker, a route) can derive the placement algorithmically from structural data already held authoritative — the sparsest region, the point where two measures cross — instead of an author choosing where by eye. The placement then answers to the structure, not to a remembered decision.
  • why such value goes unrouted: a mechanic never abstracted out of its engine-specific form cannot cross a project boundary — the idea is portable but the code reads as terrain-shaped, so no sibling ever calls it.
  • routing shape: a way in → a small module reading the structure's own vertex/edge data → an act → compute one derived siting instead of an authored coordinate, offered as a note and never auto-applied — the hand still does the placing → a visible consequence → a placement that changes when the underlying structure changes, that no one had to pick by eye.
