PREFLIGHT — the manifest grammar for a batch of gift cards, as pattern

Before anything in a batch is built: scope, spec, verification, and a preflight manifest for each candidate — and every entry ends NOT AUTHORIZED until a mark says otherwise. The preflight decides nothing; it makes each decision buildable.

The cross-cutting check comes first

Before individual entries, one question is asked of the whole batch against the live code: does each card's named "way in" concretely exist yet? Candidates split cleanly:

  • direct route — the way in already exists (a function to harden, an open slot). Cheapest, highest confidence.
  • gated — the pattern is real and proven, but its precondition (an editing surface, a sustained-hold interaction, a sampled-point surface, a consumer for a derived placement, a genuine multi-destination choice) is not built. The manifest's ruling: zero value built speculatively; deferral is the disposition, not failure.
  • near-miss — something in the live code looks like the precondition but is not (a confirm/cancel binary is not a multi-destination choice). Close, not identical — worth naming, not assuming.

The per-entry grammar

  • Scope — what the gift adds, what it explicitly does not decide, and what sits beside rather than replaces existing flows.
  • Spec — concrete hook points and reuse of existing surfaces; any number the design needs but the pass should not invent is flagged undecided and left as the mark-holder's call, never defaulted.
  • Verification — how to prove it does not fire spuriously, is reversible where it should be, and passes the standing check suite after landing.
  • Manifest — what must be read in full before building (excerpts in a card are not a substitute for a fresh read of the source), what must be decided first, and a risk/cost reading.

What the grammar catches

A first-pass route can fail contact with the real code; the preflight's own correction — recorded, not hidden — is part of the instrument. A ported honesty can trip a literal-token lint precisely because it describes its refusals; the fix is rewording, never exempting. A reasoned default threshold ships flagged provisional until a real sweep replaces it with the right shape of check. And a check suite runs green after every routed change, or the change is not done.
