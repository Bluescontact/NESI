# GIFT — ratify by crossing, not by naming

- **pattern:** a tentative relationship is confirmed by a gesture, not a dialog. Proposed edges are visual only — they stretch and go slack, applying no force. Carry the object physically across a boundary and the geometry itself decides: did the connecting line actually cross the seam during the drag? If yes, the edge ratifies and becomes real; cross back and it reverts. No typed label, no click-to-confirm, no "success" toast — the spatial fact (a taut line where there was a slack one) is the only acknowledgment.
- **source shape:** built and working in an earlier bench tool for reviewing staged objects.
- **capacity:** wherever a system already lets the hand arrange things by drag, this offers a second, embodied route to the same hand-confirmed fact its textual declare-flow produces — that two things are really related, not merely near. It sits beside the text flow, not in place of it: naming what the relationship is still takes words; this only confirms that one exists.
- **why such value goes unrouted:** a mechanism built for an entirely different tool and object type is never read against the project that needs it — the interaction is general but its host makes it look specific.
- **routing shape:** a way in → existing drag-to-arrange physics → an act → on a crossing, open the same staged-confirm surface the textual flow already uses, pre-filled → a visible consequence → a second, physical route to the one place a person's own judgment enters the structure. What counts as "close enough" is a real design choice the pattern does not make for you — and a later sweep of one port showed why: a radius-sum proxy false-ratified broadly; exact rectangle overlap needed no tuned constant at all.
- **reading:** capacity: M · effort: M · confidence: M
